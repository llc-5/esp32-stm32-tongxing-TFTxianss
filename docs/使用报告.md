# ESP32-S31 摄像头 → STM32F103 转屏系统 · 使用报告

> 版本：SPI 传输版（V7）　|　仓库：`https://github.com/llc-5/esp32-stm32-tongxing-TFTxianss`　|　报告日期：2026-11-27

---

## 1. 这套系统是做什么的

ESP32-S31 连接 DVP 摄像头（OV2640 / OV5640 自动识别）采集画面，通过 **SPI**把每一行像素逐行发给 STM32F103CBT6；STM32 收到后直接写到 ILI9341（240×320）TFT 屏上。画面为 240×240 RGB565，在屏幕上垂直居中（上下各留 40 像素蓝边）。

因为 STM32F103CBT6 只有 20KB SRAM，放不下整帧（240×240×2 = 115200 字节），所以协议采用**逐行流送**：一包只发一行，收到立刻写屏，不缓存整帧。

这一版把两个瓶颈一起换掉了：

1. **通讯从 UART 2Mbps 改成 SPI 8MHz**（同样的四根杜邦线，不用改接线）；
2. **写屏从"GPIO 软件模拟 SPI"改成硬件 SPI1 @18MHz**——这一步更关键，之前写一帧屏要 390ms，比通讯本身还慢。

预期帧率从 **约 1fps 提升到 5~6fps**。

## 2. 硬件接线

### 2.1 摄像头 → ESP32（16 根，位置不变）

| 上排丝印 | GND | SCL | SDA | D0 | D2 | D4 | D6 | PCLK | PWDN |
|---|---|---|---|---|---|---|---|---|---|
| ESP32 | GND | GPIO3 | GPIO4 | GPIO35 | GPIO38 | GPIO0 | GPIO2 | GPIO46 | 不接 |

| 下排丝印 | 3.3V | VSYNC | HREF | RST | D1 | D3 | D5 | D7 | FLASH |
|---|---|---|---|---|---|---|---|---|---|
| ESP32 | 3.3V | GPIO48 | GPIO49 | 不接 | GPIO37 | GPIO39 | GPIO1 | GPIO47 | 不接 |

模块自带 24MHz 有源晶振，**没有 XCLK 脚，不要接 XCLK**。这块排针容易接触不良，若串口报 `get sensor ID failed`，先重新插拔排针再复位。

### 2.2 ESP32 → STM32（SPI，3 根信号 + READY + 共地）

| 信号 | ESP32-S31 | STM32F103 | 方向 |
|---|---|---|---|
| SCK | **GPIO45** | **PB13**（SPI2_SCK） | ESP32 → STM32 |
| MOSI | **GPIO44** | **PB15**（SPI2_MOSI） | ESP32 → STM32 |
| CS | **GPIO43** | **PB12**（SPI2_NSS） | ESP32 → STM32 |
| READY | **GPIO42** | **PB10** | STM32 → ESP32 |
| GND | GND | GND | **必须共地** |

SPI mode 0（CPOL=0 / CPHA=0），MSB first，8 bit，主机 8MHz。线尽量短（<20cm）；**共地不良是高速 SPI 出误码的头号原因**。

这四根线就是原来 ESP32 直接驱动 ILI9341 用的那四根，插回去即可，没有新增接线。

### 2.3 ILI9341 → STM32

RES=PA0、CS=PA1、DC=PA2、SCK=PA5、SDI=PA7、LED=PA4，VCC 接 3.3V（**不要接 5V**）。两块板 3.3V 各自供电，只共地、不并接。

注意：**PA5/PA7 现在由 STM32 的硬件 SPI1 驱动**（原来是 GPIO 逐位翻转模拟的），所以这两根线比原来更"快"，副作用是如果屏幕出现花屏/错位，把 `ili9341.h` 里的 `LCD_SPI_BR` 从 `0x01`（18MHz）改成 `0x02`（9MHz）即可。

完整接线图见 `docs/引脚接线图.html`（浏览器可打开打印）。

## 3. 编译与烧录

### 3.1 ESP32 发送端

需要 ESP-IDF 6.2 环境。工程在 `esp32-s31-sender/`。

```powershell
cd esp32-s31-sender
.\flash.ps1 -Port COM10      # 编译 + 烧录 + 自动读串口验证
```

- 端口按实际改（可用设备管理器查 CP210x 对应的 COM 号）。
- 脚本会自动做全量重编、分块烧录、hash 校验，最后读 8 秒串口。
- 只重新编译不烧录：`idf.py build`。
- 成功标志：串口出现 `CAM SENDER BUILD: <时间>`、`Detected Camera sensor PID=0x26`、`stream started`。

### 3.2 STM32 接收端

用 Keil MDK-ARM（μVision）打开 `stm32f103-receiver/Project.uvprojx`：

1. 确认 Device 为 **STM32F103CB**；
2. 确认 Include Paths 含 `.\User`（`link_proto.h` 所在目录）；
3. **Rebuild** → 烧录（ST-Link / 串口均可）。

注意：SPI2 从机和 DMA 都是**纯寄存器初始化**，工程里**不需要**添加 `stm32f10x_spi.c / stm32f10x_dma.c`（虽然 Library 里有，但代码没调用其中的函数）。

成功标志：屏幕顶栏显示 **`V7`**（SPI 版标识；显示 `V6` 说明烧的还是旧 UART 版，两者接线不同，必须重烧）。

## 4. 传输协议

每行一包 **485 字节**，ESP32 用一次 SPI 事务发完（CS 包住整包）：

| 字节 | 含义 |
|---|---|
| 0 | magic1 = 0xA5 |
| 1 | magic2 = 0x5A |
| 2 | 帧号（0~255 循环，仅调试） |
| 3 | 行号（0~239） |
| 4 | 异或校验（magic1^magic2^帧号^行号^480 字节像素） |
| 5~484 | 240 个 RGB565 像素，高字节在前 |

**握手流程**：

1. STM32 先把 SPI2-RX 的 DMA 武装成 485 字节，**然后**才把 PB10(READY) 拉高；
2. ESP32 等 READY=1 → CS 拉低 → 送出 485 字节 → CS 拉高；
3. STM32 的 DMA 收满立刻拉低 READY（用 DMA 而不是逐字节中断，是因为 SPI 从机没有流控，8MHz 下 1 字节只有 1µs，边收边写屏必然溢出——这正是上一版 SPI 一包都收不到的根本原因）；
4. 校验 magic + 整包异或，通过就写屏，然后回到第 1 步。

行号必须从 0 连续递增；中途丢包就丢弃这一帧的剩余部分，等下一个行 0 重新对齐，避免画面写串位。

## 5. 屏幕调试计数怎么看

屏幕顶栏一行大字，三页轮换：

| 页面 | 显示 | 含义 |
|---|---|---|
| 第 1 页 | `K` / `T` | 有效行数 / 收包超时次数 |
| 第 2 页 | `C` / `G` | 异或校验错 / magic 错 |
| 第 3 页 | `W` / `R` | 行号错 / **一包里最多收到过多少字节**（485 = 收满） |

**判断方法**：

- `K` 持续增长、`T/C/G/W` 基本不动 → 通讯正常，画面应逐渐出来；
- `K=0`、`T` 增长 → STM32 没收到 SPI 数据，依次查：① 是否已烧 V7；② GPIO43/44/45 ↔ PB12/13/15 是否接对（**SCK/MOSI 接反是最常见的**）；③ 有没有共地；
- `C` 增长（异或错）→ 收到数据但内容错了，典型是 SPI 时钟太快或杜邦线太长/没共地，把两端 `LINK_SPI_HZ` 从 8000000 降到 4000000；
- `G` 增长（magic 错）→ 字节错位，通常与 `C` 同时出现，处理同上；
- `W` 增长 → 中途丢包，程序会丢弃残帧并从行 0 重新对齐；
- `R = 0` → SPI 时钟或片选根本没进来，查 SCK(GPIO45→PB13)、CS(GPIO43→PB12)；
- `R` 在 1~484 之间 → 时钟通了但没收满，查 MOSI(GPIO44→PB15)、共地、线长；
- `R = 485` 但 `K` 不涨 → 收满了，看 `C`/`G`（内容错，不是没收到）；
- 顶栏三页都不轮换 → 主循环卡死。

## 6. 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 串口 `ov2640: get sensor ID failed` | 摄像头排针接触不良，重插 2×9 排针、量 3.3V，复位 ESP32（无需重烧） |
| 屏幕全蓝、连顶栏 `V7` 都没有 | 屏本身没工作：查 PA0/PA1/PA2/PA5/PA7 与背光 PA4；或 SPI1 太快，把 `LCD_SPI_BR` 改成 `0x02` |
| 顶栏 `V7` 正常但画面区一直蓝 | 链路没通，按第 5 节看 `T`；或行长错位看 `C/G` |
| 画面花屏/斜条纹 | 屏 SPI 太快（`LCD_SPI_BR` → `0x02`）或链路误码（`LINK_SPI_HZ` → 4000000） |
| 画面红蓝反了 | 把 `camera_preview.h` 的 `CAM_SWAP_RGB565` 改成 0，重编两端 |
| 文字/画面上下颠倒 | 调整 `ili9341.h` 的 `LCD_MADCTL_VALUE`（当前 0x48） |
| 帧率只有 5~6fps | 已把通讯和写屏两个瓶颈都换掉；再往上要走"收下一行"与"发上一行"的 DMA 重叠，属于下一阶段 |
| 摄像头起不来但想先验证连线 | ESP32 会自动进入 **SPI 链路自测**：发彩条图案。屏上出现彩条 + `K` 增长，就说明 4 根线是通的，问题只在摄像头 |
| Keil 报找不到 `link_proto.h` | Include Paths 加 `.\User` |
