## 三、工作过程（UART）

1. ESP32 初始化摄像头（OV2640 请求 240×240 RGB565；OV5640 退回 800×600 后裁剪缩放），摄像头脚位与原工程完全一致。
2. ESP32 等 STM32 把 PB10(READY) 拉高，表示可以发下一行。
3. ESP32 经 UART1 TX(GPIO43) 发 485 字节：`A5 5A | 帧号 | 行号 | 异或 | 480 字节 RGB565`，发完等硬件全部送出。
4. STM32 的 USART1 RX(PA10) 收到首字节立即把 PB10 拉低，防止下一包覆盖；收满 485 字节后校验 magic / 异或 / 行号。
5. STM32 立即把 480 字节 RGB565 写到 ILI9341 对应行（240×240 居中，Y 起点 40）；行号 0 开始新的一帧。
6. STM32 写完这一行再拉高 PB10，重复 2~5，直到 240 行全部显示。

## 四、排错速查

- **屏幕只显示蓝色 + 顶栏计数**：正常，说明程序在跑。看顶栏 `V6` 确认是 UART 版。
- **`T` 持续增长、`K` 不动**：ESP32 的 TX 没送到 STM32 RX。查 GPIO43 → PA10、共地、电平时 STM32 是否已烧录。
- **`G` 增长**：magic 错，通常是线太长/波特率太高。两端同时把 `LINK_UART_BAUD` 改成 `1000000UL` 重编重烧。
- **`C` 增长**：异或校验错，同样是串口丢字节，处理同上。
- **`W` 增长**：行号错，中间丢了一包；程序会丢弃残帧并从行 0 重新对齐。
- **`L` 不动但 `T` 不动**：主循环卡住，检查是否进入了某个死循环。
- **颜色红蓝反了**：把 `camera_preview.h` 里的 `CAM_SWAP_RGB565` 改成 0，两端重新编译烧录。
- **文字/画面上下颠倒**：调整 `ili9341.h` 里的 `LCD_MADCTL_VALUE`（当前 `0x48`）。
- **摄像头初始化失败**：先确认 OV2640 的 `PID=0x26` 日志；再查 3.3V 电流和 16 根 DVP 线。
