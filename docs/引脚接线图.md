# ESP32-S31 摄像头 → STM32F103CBT6 TFT 接线图（SPI 版 V7）

> 摄像头位置**完全不变**（沿用 `sxtxs` 工程的 16 根线），只把 TFT 从 ESP32 拔下来，改接 STM32。
> 两端供电各自独立，但 **GND 必须共地**。
> 双机通讯为 **SPI**：4 根信号线 + 共地。这 4 根就是原来 ESP32 直接刷屏用的那几根，接回去即可。

## 一、总览

```
   OV2640/OV5640              ESP32-S31                  STM32F103CBT6            ILI9341 240x320

   │ 8位 DVP  │──16根─────▶│ 摄像头采集   │          │ TFT 驱动      │──6根──▶│ TFT 屏   │
```

## 二、摄像头模块 → ESP32-S31（**不动**，原工程接线）

模块正面 2×9 排针丝印顺序：

| 上排 | GND | SCL | SDA | D0 | D2 | D4 | D6 | PCLK | PWDN |
|---|---|---|---|---|---|---|---|---|---|
| **ESP32 引脚** | GND | GPIO3 | GPIO4 | GPIO35 | GPIO38 | GPIO0 | GPIO2 | GPIO46 | 不接 |

| 下排 | 3.3V | VSYNC | HREF | RST | D1 | D3 | D5 | D7 | FLASH |
|---|---|---|---|---|---|---|---|---|---|
| **ESP32 引脚** | 3.3V | GPIO48 | GPIO49 | 不接 | GPIO37 | GPIO39 | GPIO1 | GPIO47 | 不接 |

- 模块自带 24MHz 有源晶振，排针**没有 XCLK 脚**，ESP32 不输出 XCLK。
- GPIO37 是 strapping 脚，原工程已验证可用；不要改用 GPIO36。

## 三、ESP32-S31 → STM32F103CBT6（SPI，3 根数据 + 1 根握手 + 共地）

这 4 个 ESP32 脚都是原工程接 TFT 的脚，屏幕移走后直接复用：

| 信号 | ESP32-S31 GPIO | STM32F103CBT6 引脚 | 方向 | 说明 |
|---|---|---|---|---|
| SCK | **GPIO45** | **PB13**（SPI2_SCK） | ESP32 → STM32 | **mode 0，8MHz**，MSB first |
| MOSI | **GPIO44** | **PB15**（SPI2_MOSI） | ESP32 → STM32 | 单向，STM32 不回数据 |
| CS | **GPIO43** | **PB12**（SPI2_NSS） | ESP32 → STM32 | 一次事务包住整包 485 字节 |
| READY | **GPIO42** | **PB10** | ESP32 ← STM32 | STM32 拉高表示 DMA 已武装、可以发；收满立刻拉低 |
| GND | GND | GND | 共地 | **必须接，这是高速 SPI 误码的头号原因** |

- **SCK 和 MOSI 接反是最常见的接错**，对调后表现为 `G`（magic 错）计数飞涨。
- 接线尽量短（建议 <20cm）。若 `C`/`G` 计数持续增长，把两端 `LINK_SPI_HZ` 一起从 `8000000UL` 改成 `4000000UL`。
- GPIO40 / GPIO41 空着（40 是 strapping 脚，避开）。

## 四、ILI9341 TFT → STM32F103CBT6（从 ESP32 原接线照搬）

| TFT 屏引脚 | STM32F103CBT6 | 说明 |
|---|---|---|
| RES / RESET | **PA0** | 复位 |
| CS | **PA1** | 片选（软件控制） |
| DC / RS | **PA2** | 命令/数据选择（软件控制） |
| SCK | **PA5** | SPI1_SCK，**硬件 SPI1 @18MHz** |
| SDI / MOSI | **PA7** | SPI1_MOSI，硬件 SPI1 |
| LED / 背光 | **PA4** | 代码中 `LCD_LED_CTRL=1`，由 PA4 控制；也可改接 3.3V 常亮 |
| VCC | 3.3V | **不要接 5V**，屏模块必须是 3.3V 兼容 |
| GND | GND | 与 STM32、ESP32 共地 |
| SDO / 触摸脚 | 不接 | 原工程未使用 |

> PA5/PA7 原来是 GPIO 逐位翻转模拟 SPI（写一帧要 390ms）。现在交给 STM32 的硬件 SPI1，
> 同样数据量只要 ~51ms。屏对时钟敏感，若出现花屏/斜纹，把 `ili9341.h` 的 `LCD_SPI_BR`
> 从 `0x01`（18MHz）改成 `0x02`（9MHz）。

## 五、供电与电平注意

1. 摄像头由 ESP32 板 3.3V 供电，电流不足会初始化失败（原工程已有重试）。
2. TFT 由 STM32 板 3.3V 供电；两块板的 3.3V **不要互相并接**，只共地。
3. 若 TFT 是 5V 屏，PA0/PA1/PA2/PA5/PA7 需要电平转换，否则可能损坏 STM32。
4. SPI 线要短、要共地；误码表现为 `C`（异或错）/`G`（magic 错）增长，先把 `LINK_SPI_HZ` 降到 4MHz 验证。

## 六、协议与性能

- 每行一包 **485 字节**：
  `A5 5A | 帧号 | 行号(0~239) | 异或校验 | 480 字节 RGB565(高字节在前)`
- 双 magic（`A5 5A`）便于错位后重新同步。
- 握手：STM32 先武装 SPI2-RX 的 DMA（485 字节）→ 拉高 PB10 → ESP32 发一包 → DMA 收满立刻拉低 PB10 → 校验并写屏 → 再拉高。
- STM32 收到一行立即写屏，不缓存整帧（STM32F103CBT6 只有 20KB SRAM）。
- 链路理论上限：485B × 240 行 ÷ 8MHz ≈ **116ms/帧（8.6fps）**；屏写入约 51ms/帧。
  两者串行相加，实测预期 **5~6fps**（比 UART 版的 ~1fps 快 5 倍以上）。
  再往上需要把"收下一行"和"发上一行"用 DMA 重叠起来，属于下一阶段。
- 屏幕顶栏显示调试计数：
  - 第 1 页：`K` 有效行、`T` 收包超时
  - 第 2 页：`C` 校验错、`G` magic 错
  - 第 3 页：`W` 行号错、`R` 一包里最多收到过多少字节（485 = 收满，0 = 时钟没进来）
  - 显示 `V7` 表示 SPI 版；`V6` 是旧的 UART 版（接线不同，必须重烧）。
